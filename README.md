# v2 — 자동매매 봇

기존 루트의 `main*.py` / `paper_bot.py`는 개념 검증용 임시 코드.
v2는 지표·리스크·체결을 분리해 실시간과 리플레이가 같은 엔진을 사용한다.

## 대상

| 종목 | 성격 | 진입 근거 |
|---|---|---|
| BTC | 회귀채널 복귀 | 1시간 100봉 회귀채널 반대편 이탈 후 채널 밖 2% 지정가 |
| BTC | 25배 단기 채널(실험) | 15분 상승채널 하단 롱·하락채널 상단 숏, 5분봉 체결 |
| XRP | 패턴 단타 | 유동성 스윕, 플래그, 볼린저 스퀴즈, RSI 다이버전스 등 |

전략은 각각 독립적으로 신호를 내고, 로그에 `strategy` 태그를 남겨 성과를 따로 집계한다.

## 디렉터리

```
config/       파라미터 중앙 관리 (하드코딩 금지)
core/         거래소 API, 캔들 수집/정제
indicators/   순수 계산 함수 (ATR, MA, MACD, RSI, 볼린저, 회귀채널, 피벗, VPVR 등)
strategies/   진입 신호 생성. indicators만 사용하고 주문은 내지 않는다
risk/         포지션 크기 역산, 손절/트레일링, 리스크 상한
engine/       가상 체결, 상태 저장/복구, 메인 루프
reporting/    CSV/JSONL 로그, 디스코드 알림
tools/        수동 점검용 스크립트 (실통신 확인, 차트 출력)
tests/        단위 테스트
data/         로그·캐시 출력 (git 제외)
```

## 실행 환경

루트의 `.venv`는 Python 3.9라 v2 문법(`X | Y` 애너테이션)을 실행하지 못한다.
v2는 자체 venv를 쓴다.

```bash
cd v2
python3 -m venv .venv
./.venv/bin/pip install httpx pandas numpy matplotlib pytest

./.venv/bin/python -m pytest tests/ -q       # 단위 테스트
./.venv/bin/python -m tools.check_candles    # 거래소 실통신 점검
./.venv/bin/python -m tools.fetch_history    # 과거 캔들 백필 (재실행 시 증분)
```

## 데이터 제약

Gate.io REST API는 타임프레임당 **최근 10,000봉까지만** 돌려준다. 초과 요청은
400(`Candlestick too long ago`)이다. 다만 Gate 공식 월별 Historical Quotation
Data로 이전 구간을 보강할 수 있다. REST만 사용했을 때의 최대 깊이는 다음과 같다.

| | 봉 수 | 기간 |
|---|---|---|
| BTC 1d | 800 | 799일 |
| BTC 1h | 9,600 | 400일 |
| XRP 1h | 9,600 | 400일 |
| XRP 5m | 9,216 | **32일** |

XRP 5분봉은 공식 월별 아카이브로 180일 이상 보강한다. 아카이브는 완결된 달,
REST는 현재 달과 중복 구간을 담당하며 중복 시 REST 값을 우선한다.

```bash
./.venv/bin/python -m tools.fetch_gate_archive \
  --contract XRP_USDT --interval 5m --days 180
```

## 설계 원칙

**1. 지표는 순수 함수로.**
입력은 DataFrame + 파라미터, 출력은 값. 전역 상태나 I/O를 넣지 않는다.
실시간 루프와 과거 데이터 검증에서 같은 함수를 재사용하기 위함이다.

**2. 미래 정보 참조 금지.**
피벗 등 확정 지연이 있는 계산은 `as_of` 인자를 필수로 받는다.
과거 데이터로 파라미터를 고를 때 이걸 빠뜨리면 결과가 실제보다 좋게 나온다.
다중 시간봉 리플레이는 캔들 시작 시각이 아니라 `시작 + 봉 길이`가 판단
시각을 지난 봉만 사용한다. 시장가 신호는 신호봉 종가가 아닌 다음 5분봉
시가에 체결해, 봉 마감 후 실제로 처음 주문할 수 있었던 가격을 쓴다.

**3. 레버리지는 원칙적으로 결과값이다.**
손절 위치 → 손절 거리 → 포지션 크기 → 레버리지 순으로 계산한다.
레버리지를 먼저 정하지 않는다. 청산가는 손절가보다 최소 3배 멀어야 한다.
`btc_regime_25x`만 고정 레버리지 자체를 검증하는 별도 고위험 실험이라,
잔고 10% 격리증거금과 25배를 명시적으로 덮어쓴다.

**4. 진입하지 않은 신호도 기록한다.**
리스크 상한이나 필터에 걸려 스킵된 신호도 가상 결과를 남긴다.
그래야 "막았던 신호가 실은 더 좋았는지"를 나중에 판단할 수 있다.

**5. 롱/숏은 따로 집계한다.**
크립토는 상승 편향이 있어 같은 규칙이라도 방향별 통계가 다르다.
합쳐서 보면 한쪽이 다른 쪽을 가린다.

**6. 알림 실패가 매매를 막지 않는다.**
디스코드 웹훅은 try/except로 감싸고, 실패해도 루프는 계속 돈다.

## 검증 절차

1. 지표별 단위 테스트
2. 과거 데이터에 그려서 눈으로 확인 (자동 탐지된 스윙이 납득 가능한가)
3. 가상거래 실시간 투입, 장기간 로그 수집
4. 전략별/방향별 성과 비교 — 수수료 차감 후 기준
5. 실전 전환은 충분한 표본 확보 이후, 최소 금액부터

표본이 부족한 상태에서 나온 수익률은 판단 근거가 되지 않는다.

## 결정된 사항 (2026-08-05)

- **BTC 진입(2026-08-07 교체)**: 1시간봉 100봉 롤링 회귀채널을 쓴다.
  하락 채널 상단 이탈은 상단선 2% 위 숏 지정가, 상승 채널 하단 이탈은
  하단선 2% 아래 롱 지정가를 12봉 동안 둔다. 채널선에서 절반 익절한 뒤
  나머지는 트레일링한다. 1% 이격은 같은 표본에서 손실이 커 제외했다.

- **BTC 25배 단기 채널(2026-08-10 교체)**: 15분봉 48개(약 12시간)의
  롤링 회귀채널로 짧은 흐름을 본다. R² 0.55 이상이고 회귀 기간 전체
  이동폭이 0.4% 이상일 때만 상승·하락 채널로 인정한다. 상승채널 하단에는
  롱, 하락채널 상단에는 숏 post-only 지정가를 두고 5분봉으로 체결한다.
  채널 끝이 현재가에서 0.5%보다 멀면 기다리며 주문은 3봉 뒤 취소한다.

  잔고 10%를 가상 증거금으로 삼아 25배 수량을 계산한다. 아직 실제 격리마진
  예약·강제청산을 구현한 것은 아니다. 진입과 익절은 메이커이며 목표가는
  메이커 비용을 차감하고도 **전체 계좌가 2% 증가**하도록 계산한다. 이는
  증거금 순수익률 20%이며 현재 비용 가정에서 BTC 가격 이동 약 0.78%다.
  익절과 같은 가격폭(약 0.78%)의 반대편은 시장가 손절(계좌 약 -2.16%)로
  둔다. 시간 경과만으로 종가
  청산하지 않고 손절선 또는 익절선이 체결될 때까지 유지한다. 하루 최대 12회,
  3연속 손실이면 다음 UTC 날짜까지 중단한다.

  2024-01-01~2026-07-31 실시간 근사 리플레이는 완료 1,385건과 미청산 1건,
  승률 51.6%, 수익률 -41.2%, 실현잔고 최대낙폭 64.8%였다. 목표 익절은
  714건으로 평균 계좌 +1.995%, 시장가 손절은 671건으로 평균 계좌
  -2.158%였다. 시간청산은 0건이다. 손익 합계는 익절 +10,848.42 USDT,
  손절 -11,260.30 USDT다. 손익분기 승률 약 51.96%보다 실제 승률이 낮으므로
  손실이 남았다. 방향별로는 롱 +38.98 USDT, 숏 -450.87 USDT였다. 따라서
  현재 구조는 수익 전략이 아니며 페이퍼 검증용이고 실거래 배포 금지다.

- **손절**: 구조적 위치 + ATR 버퍼. 하한은 왕복 테이커 비용의 2배(≈0.38%)로
  수수료에서 유도한다(`RiskConfig.min_stop_pct`). 이보다 좁으면 이겨도
  수수료가 수익의 절반을 가져간다.
- **레버리지**: 일반 전략은 손절 거리에서 역산하되 전략별 상한을 둔다
  (`LEVERAGE_CAP`: BTC 3x / XRP 5x). `btc_regime_25x`는 별도 고정 25배
  실험이며, 청산거리 하한도 손절의 3배로 명시적으로 분리한다.
- **분할 진입**: 총 리스크 1%를 0.4 / 0.3 / 0.3으로 먼저 쪼갠다
  (`TRANCHE_RISK_WEIGHTS`). 손절은 포지션 전체에 하나만 둔다.
- **비용 포함 사이징**: 1% 리스크에는 손절 가격차뿐 아니라 예상 진입·청산
  수수료와 양방향 슬리피지를 처음부터 포함한다. 기본은 테이커/테이커,
  지정가 진입과 스트레스 조건은 `ExecutionAssumption`으로 따로 계산한다.
- **봉 처리 순서**: 직전 봉까지 확정된 손절·목표를 먼저 검사하고, 청산이
  없을 때만 완료된 현재 봉으로 트레일을 갱신한다. 새 트레일은 다음 봉부터
  유효하다. 손절을 건너뛴 갭은 손절가가 아니라 시가에서 시장가 슬리피지를
  반영해 체결한다.
- **동시 리스크**: 실측 상관 모형이 생기기 전에는 방향과 무관하게 열린
  포지션의 손절 리스크를 100% 합산한다.
- **XRP 익절**: VPVR 대신 1.5R 부분익절 + 0.7 ATR 트레일링 + 40봉 시간 손절
  (`ScalpConfig`). 1:1 목표는 수수료 차감 후 손익분기 승률이 69%라 성립하지 않는다.
